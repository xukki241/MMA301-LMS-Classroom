# LMS-10 teacher mobile flow

## Approved scope

Implement the teacher mobile flow using completed LMS-08/09 APIs. LMS-27 screens, student-side acceptance checks, and backend changes are excluded. Use seeded submissions and teacher API read-back. Display the existing required Submission.studentId field with submission time; do not invent student names or join Auth data.

## Design

Reuse Expo Router, React Native Paper, TanStack Query, the existing HTTP client, theme, and shared screen states. Add teacher Exercise list, creation, submission list, and submission detail/grading screens beneath a protected class-scoped route. Auth restoration must finish before fetching. Non-teachers cannot open these screens; server authorization remains authoritative. Verify class ownership from fresh class data before mounting feature screens.

Create takes trimmed title (1–200), description (up to 10,000), and a future local deadline converted to ISO. Explicit date/time fields use YYYY-MM-DD and HH:mm, validate calendar dates, and show the device timezone. Keep input on errors, disable duplicate saves, never automatically retry creation. No edit/delete Exercise scope.

Submission rows show full student ID, submitted time, and grade/ungraded state. Detail shows content and an HTTP(S) link. Grade score is a finite decimal 0–10, feedback up to 10,000. Existing grade prefills the form. Grading opens at dueAt; server GRADING_NOT_OPEN remains authoritative if device time differs. Preserve drafts on failed writes and avoid overwriting edits on refetch. Successful saves refresh list/detail caches. Grade 0 must display correctly.

No single Exercise endpoint exists: load its class list and find the selected ID on direct navigation. Invalid/missing IDs and 401/403/404 produce deliberate states, not stale content or crashes. No feature queries before authorization. New scoped queries include user identity; logout uses the existing cache clear.

## Acceptance

- Teacher creates an Exercise and sees it persist through API read-back and reload.
- Teacher opens seeded Submission content, grades and regrades, and sees the saved grade through teacher API reads.
- Loading, empty, retry, permission, expired-session, missing-resource, validation, and network-error states are usable.
- Mobile typecheck, focused behavior tests, and Expo Android bundle/export pass; Android runtime evidence is required separately from bundle success.
- Screenshots/runtime evidence and reproducible local fixture instructions document verification. No LMS-27 completion claim.

## Implementation choices

Use existing lms-10 branch and checkout (clean at start, HEAD 6f903ff). Native date/time fields avoid adding a product dependency; the format and timezone are visible. Keep the backend authoritative for deadlines. Tests use Node's runner with a TypeScript transpile hook and a real local HTTP test server, avoiding a new application test dependency.
