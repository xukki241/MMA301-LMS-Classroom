# LMS-08 Core API Exercise — Implementation Plan

> **For agentic workers:** Use the executing-plans skill to implement this plan task-by-task after the user requests implementation. Steps use checkboxes for tracking.

**Goal:** Giáo viên sở hữu lớp tạo bài tập; thành viên lớp xem danh sách, với JWT, kiểm tra quyền và hạn nộp đúng yêu cầu.

**Architecture:** Bổ sung route → controller → service trong Core API hiện tại. Tái sử dụng Exercise, ClassModel, ClassMember, requireAuth, asyncHandler và HttpError; không tách service mới hay thay đổi Auth Service.

**Tech Stack:** TypeScript, Express 4, Mongoose 8, Zod 3, MongoDB; test HTTP dùng fetch và node:assert/strict chạy bằng tsx.

**Spec:** https://app.notion.com/p/LMS-08-Core-API-Exercise-3d41a3267e3e81da9027f9273d827c84 (nội dung đã đọc trong phiên này).

## Global Constraints

- Teacher chỉ tạo trong lớp mình sở hữu. Student POST trả 403.
- dueAt trong quá khứ trả 400; đề xuất yêu cầu dueAt lớn hơn thời điểm server xử lý.
- createdBy lấy từ JWT, classId lấy từ URL; không lấy hai trường này từ body.
- Không thay đổi hành vi LMS-05/LMS-06 hoặc thêm dependency nếu không cần.
- Chạy test tạo dữ liệu trên database local/test; không sử dụng dữ liệu production.

## Contract đề xuất

| Method | Route | Thành công |
|---|---|---|
| POST | /classes/:classId/exercises | 201, { message, exercise } |
| GET | /classes/:classId/exercises | 200, { exercises: [] } |

Body POST:

```json
{ "title": "Bài tập 1", "description": "Nội dung bài tập", "dueAt": "2027-01-01T16:59:00.000Z" }
```

Ngày trên chỉ minh họa; test phải tự tạo hạn nộp tương lai. Contract đề xuất: title trim, 1–200 ký tự; description tùy chọn, mặc định chuỗi rỗng, tối đa 10000 ký tự; dueAt bắt buộc là ISO 8601 có timezone, lưu UTC. Các giới hạn độ dài là lựa chọn thiết kế, không phải yêu cầu đã ghi trong Notion.

Response exercise giữ _id, classId, title, description, dueAt, createdBy, createdAt, updatedAt theo model hiện tại. List sắp xếp dueAt tăng dần, _id tăng dần để ổn định khi trùng hạn; chỉ trả bài của classId đã kiểm tra quyền. Phân trang nằm ngoài phạm vi MVP này.

Lỗi theo envelope hiện có { error, code }: 401 thiếu/sai/hết hạn JWT; 403 thiếu quyền; 400 classId sai định dạng hoặc dueAt sai/không ở tương lai; 404 lớp không tồn tại; 422 title/description/body không đúng schema. Zod kiểm tra body strict để từ chối trường không hỗ trợ.

## Review Focus

1. Giáo viên của lớp khác hoặc member có role không phù hợp không được tạo: test cross-class và role/ownership độc lập.
2. Body giả mạo createdBy/classId không làm thay đổi chủ thể: test từ chối trường ngoài schema và kiểm tra dữ liệu lưu.
3. Ngày thiếu timezone, không hợp lệ hoặc quá khứ không được lưu: test từng trường hợp và timezone offset hợp lệ.
4. Danh sách không lộ bài lớp khác: tạo hai lớp, test membership và lọc classId.
5. Script không được báo pass khi API trả lỗi: dùng assertion, catch đặt process.exitCode = 1; xác nhận dữ liệu bằng request GET tiếp theo.

Ví dụ assertion trong luồng test (exerciseUrl và teacherToken được lấy từ fixture trên):

```ts
const dueAt = new Date(Date.now() + 86_400_000).toISOString();
const response = await fetch(exerciseUrl, {
  method: "POST",
  headers: { Authorization: `Bearer ${teacherToken}`, "Content-Type": "application/json" },
  body: JSON.stringify({ title: "Bài tập 1", description: "Nội dung", dueAt }),
});
assert.equal(response.status, 201);
const body = await response.json();
assert.equal(body.exercise.title, "Bài tập 1");
assert.equal(body.exercise.dueAt, dueAt);
```

## Nếu chọn toàn bộ CRUD theo DoD Gate

Trước khi viết code, mở rộng contract và test cho GET /classes/:classId/exercises/:exerciseId, PATCH và DELETE cùng đường dẫn. Read yêu cầu membership; write yêu cầu giáo viên sở hữu lớp; query luôn ràng buộc cả classId và exerciseId. Phải thống nhất với LMS-09 về xóa bài có submission (chặn xóa hay soft delete), và việc sửa dueAt của bài đã hết hạn. Không mặc định hard delete vì model Submission/Grade đã tồn tại.
