# LMS-10 Implementation Plan

> **For agentic workers:** Use executing-plans to implement task by task, then request an independent review. Track progress in docs/testing/lms-10-progress.md.

**Goal:** Deliver teacher Exercise creation, Submission review, and grading/regrading on mobile, excluding LMS-27.

**Architecture:** Class-scoped Expo Router screens use typed API clients and identity-scoped TanStack Query caches. Shared teacher ownership boundary gates all new screens. Backend contracts remain unchanged.

**Tech Stack:** Existing Expo, React Native Paper, TanStack Query, TypeScript; Node test runner.

**Spec:** ../specs/2026-09-25-lms-10-design.md

## Global Constraints

- LMS-08/09 complete; no backend implementation changes.
- No LMS-27 screens or student acceptance checks.
- Student identification uses required studentId, not names.
- Score 0–10; feedback/description at most 10,000; title 1–200; deadline future and timezone-qualified.
- Grade only at/after dueAt; server is authoritative.

## Review Focus

- Direct links during auth restoration or with wrong role/owner must not expose feature data.
- Deadline crossing and timezone/calendar errors must not produce wrong dates or permanently lock grading.
- Blank score must not become zero; actual zero must remain visible.
- Failed/ambiguous POST must preserve inputs without automatic duplicate creation.
- Refetch must not overwrite a dirty grade draft or retain another user's protected data.

## Task 1: Contracts and validation

Files: src/lib/http.ts, src/lib/query-client.ts, new src/features/exercises/{api,validation}.ts, tests/lms10.test.cjs (all under apps/mobile).

Interfaces: listExercises, createExercise, listSubmissions, getSubmission, saveGrade consume token/class IDs and return typed raw API records. Validation emits the exact create/grade bodies or field errors. HttpError adds optional code compatibly.

- [ ] Write failing behavioral tests for error-code preservation, date/calendar conversion, title/score limits, 0 versus blank, and API path/body/read-back behavior using a local HTTP server.
- [ ] Implement types/client/validation; retain error codes; use nonretrying writes and user-scoped query keys.
- [ ] Run `npm run test:lms10 --prefix apps/mobile` and `npm run typecheck --prefix apps/mobile`; expect all pass.

## Task 2: Protected navigation and Exercise screens

Interfaces: boundary provides authenticated token/user/class ID after checking owner. Screens consume Task 1 clients. Creation invalidates exercise list then replaces route with class Exercise list.

Interfaces: load Exercise from class list for direct links. List uses Submission records with grade/null; detail uses {submission, grade}. PUT {score, feedback}; invalidate both list and detail after success.
